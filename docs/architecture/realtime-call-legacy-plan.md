# Electron 实时通话与语音消息开发任务拆解清单

## 1. 文档定位

- 本文档用于把已确认的产品需求与技术方案，进一步拆解为可执行的开发任务。
- 对应文档：
  - 计划总览：`task_plan.md`
  - 技术方案：`docs/realtime-calling-technical-design.md`
- 本文档目标：
  - 覆盖本轮全部已确认需求
  - 明确任务阶段、依赖关系、交付物与验收标准
  - 为后续排期、分工和实施提供直接依据

## 2. 需求覆盖范围

本任务清单覆盖以下已确认需求：

- 单聊实时语音通话
- 单聊实时视频通话
- 群聊实时语音 / 视频通话
- 语音消息
- 单条语音消息最长 `60` 秒
- 语音消息少于 `1` 秒不发送
- 实时通话不设产品时长上限
- 麦克风按钮发起语音通话
- 摄像头按钮发起视频通话
- 语音消息采用“按住说话”
- 松开发送
- 不做上滑取消
- 录音中显示波形和时长
- 麦克风权限被拒绝时提示开通权限
- 来电 `45` 秒未接听自动超时
- 同账号全部在线设备同时振铃
- 单用户单设备接通
- 单聊视频被叫无摄像头时允许仅语音接听
- 群视频成员无摄像头时允许纯语音加入
- 无麦克风时允许只看不说 / 只听不说
- 通话记录按最终接通类型记账
- 忙线直接返回
- 通话结束后生成通话记录消息
- 群聊首版上限 `8` 人
- 发起人离开不自动结束，最后一个已加入成员离开时结束
- 单聊 `P2P`
- 群聊 `LiveKit SFU`
- 自建 `coturn`
- 服务端权威状态
- `voice_message` 与 `call_record` 写入现有 `messages` 表
- 语音文件继续存储在 `MinIO`

## 3. 总体实施顺序

推荐顺序：

1. 服务端通话域基础设施
2. signaling 协议与状态同步
3. Electron 单聊语音通话
4. Electron 单聊视频通话
5. 语音消息
6. `coturn` 接入与弱网能力
7. `LiveKit` 群聊通话
8. 通话记录消息与历史展示
9. 验证、监控、运维与发布准备

依赖原则：

- 群聊通话依赖服务端通话域、signaling、`LiveKit` 基础接入。
- 单聊视频依赖单聊语音基础闭环。
- 通话记录消息依赖服务端权威状态收口。
- 语音消息不依赖 `LiveKit`，但依赖媒体上传和消息内容模型扩展。

## 4. Phase 1：服务端通话域基础设施

### 目标

- 建立实时通话所需的独立领域模型、数据库结构和基础服务层。

### 依赖

- 无

### 核心任务

#### 4.1 数据库结构

- 新增 `call_sessions` 表
- 新增 `call_participants` 表
- 评估并决定是否首版引入 `call_events` 表
- 增加相关索引、唯一约束、外键和基础枚举约束

#### 4.2 服务端领域服务

- 新增 `call_service`
  - 创建通话
  - 更新通话状态
  - 结束通话
- 新增 `call_participant_service`
  - 创建参与者记录
  - 设备振铃状态维护
  - 单用户单设备接通收敛
- 新增 `call_record_service`
  - 根据最终通话状态生成通话记录消息
- 新增 `turn_credential_service`
  - 为客户端签发短期 TURN 凭证

#### 4.3 规则实现

- 实现 `45` 秒超时
- 实现忙线判定
- 实现同账号全部在线设备振铃
- 实现单用户单设备接通

### 交付物

- 数据库 migration
- 服务端通话域 service 层
- 领域模型与状态枚举常量

### 验收标准

- 服务端可创建和维护通话会话
- 超时、忙线、多设备振铃、单设备接通规则可在服务层成立

## 5. Phase 2：signaling 协议与状态同步

### 目标

- 在现有 `WebSocket` 基础上补齐 `call.*` 协议族。

### 依赖

- Phase 1

### 核心任务

#### 5.1 协议定义

- 定义请求类事件：
  - `call.invite.request`
  - `call.accept.request`
  - `call.reject.request`
  - `call.end.request`
- 定义广播类事件：
  - `call.invited`
  - `call.ringing`
  - `call.accepted`
  - `call.rejected`
  - `call.busy`
  - `call.timeout`
  - `call.ended`
  - `call.state-sync`

#### 5.2 协议字段

- 统一基础字段：
  - `call_id`
  - `conversation_id`
  - `call_scope`
  - `media_type`
  - `sender_user_id`
  - `sender_device_id`
  - `request_id`
  - `timestamp`

#### 5.3 状态同步

- 增加重连后的状态同步
- 增加非法状态迁移拒绝逻辑
- 增加服务端权威回写机制

#### 5.4 竞态处理

- 取消 vs 接听
- 超时 vs 接听
- 同用户多设备同时接听
- 通话中收到新来电

### 交付物

- `WebSocket` 事件定义
- 服务端 handler
- 状态同步逻辑
- 错误码与错误回包规范

### 验收标准

- 所有通话生命周期事件可通过 `WebSocket` 完整流转
- 服务端能正确裁决关键竞态

## 8. Phase 5：语音消息

### 目标

- 打通与实时通话分离的语音消息能力。

### 依赖

- 现有 `MinIO` 附件上传链路
- 消息内容模型扩展

### 核心任务

### 验收标准

- 语音消息可录制、发送、播放
- 60 秒上限和 1 秒下限都生效

## 13. 可并行任务建议

可并行推进：

- 服务端数据库结构 与 signaling 协议定义
- 单聊通话 UI 与服务端状态机测试
- 语音消息前端交互 与 `voice_message` 内容模型支持
- `coturn` 部署准备 与单聊通话开发

不建议并行推进：

- 群聊 `LiveKit` 通话 与单聊基础闭环同时大规模展开

原因：

- 单聊通话链路、权限处理、媒体基础和状态机问题必须先稳定，否则群聊排障难度会显著增大。

- 第一批最值得立即开始的任务是：
  1. 服务端通话域基础设施
  2. signaling 协议与状态同步
  3. Electron 单聊语音通话
